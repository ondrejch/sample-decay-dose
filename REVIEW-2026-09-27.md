# Review: full repository at `91f8fc2` (tracked files only)

- **Mode**: whole-repo review, 112 tracked files
- **Head**: `91f8fc2` (human body atom density)
- **Baseline checks**: `pytest -q` passes (93 tests). `py_compile` succeeds on all tracked `*.py` under Python 3.12. `pyflakes` reports no undefined names (21 unused imports, f-strings without placeholders).
- **Method**: five parallel reviewers split by area (core `SampleDose`, other library modules and `gw_exe`, `leaky_box_origen`, `concrete_irrad` and `play`, examples and repo metadata). Each finding was checked by deck generation, mocked `obiwan`/SCALE calls, or direct data inspection. SCALE itself was not run.
- **Verdict labels**: CONFIRMED means the behavior was demonstrated. PLAUSIBLE means the code reading is strong but SCALE-side behavior was not executed.

## Summary

The example scripts match the current library API. An AST and `inspect` cross-check of all 41 scripts found no drift after the `1f2aa48` refactor. The `REVIEW-2026-08-23` items are fixed. The isotope tables in `isotopes.py` and `data/isotopic_data.json` are internally consistent.

The highest-risk defects sit in the data and in the newest code:

1. The FGR-11 DCF CSVs contain OCR errors of up to six orders of magnitude, and H-3 is missing from all five DCF tables.
2. The `concrete_irrad` pipeline has three independent defects that each prevent a valid first SCALE run: the F33 and the decayed F71s are never staged, and the source strengths are in mole-volume units.
3. `total_dose` adds contact and handling detectors together for the two handling/contact estimators. Its uncertainty formula applies the product rule to a sum.
4. The neutron source is silently dropped whenever the `Origen` object was not run in the same process. This always happens in the radiator workflow.
5. `play/body_atom_density.py` cites the wrong ICRU report and labels its whole-body composition as soft tissue. The owner confirmed that the whole-body average is the intended quantity.

### A3. `concrete_irrad` pipeline cannot produce a valid run

All in `concrete_irrad/concrete_lid_contact_dose.py`.

- **Cuboid bounds written min-first** (`:285,287`). The deck writes `cuboid 11 -50.0 50.0 -50.0 50.0 0.0 5.0`. The KENO-VI manual lists `+X -X +Y -Y +Z -Z`, which `examples/irradiator/irradiator.py:143-149` follows. Owner clarification: KENO-VI accepts either order in most cases, so this is a consistency item. The MAVRIC `src` cuboids use min/max order and are fine.
- **Boundary uses the x half-length for y** (`:289`), CONFIRMED. `cuboid 99999 4p {hx + box_pad}` is too small for a non-square lid. With `width_cm=300` the lid spans y = +/-150 while the boundary is +/-60.1.
- **F33 is never staged** (`:126,144`), CONFIRMED. The shell block copies only `${INPDIR}/*.inp`. The deck names the library by basename, and nothing copies it into `case_dir`.
- **Decayed F71s are never copied into the MAVRIC directory** (`:348-351`), CONFIRMED. `run_mavric` checks that each file exists but does not copy it. The deck's `cp ${INPDIR}/*.f71 .` then copies nothing. `DoseEstimator.run_mavric` uses `shutil.copy2` for this step.
- **Source strengths are in mole-volume units** (`:219-220`), CONFIRMED. `get_burned_nuclide_data(..., 'gato')` returns gram-atoms (moles), and the code multiplies their sum by `r['volume']`. The docstring says photons/s. The F71 already stores whole-volume totals. `test_source_strengths_use_gato_and_volume` locks this behavior in. Suggestion: use `useNormConst` with the distribution, as `DoseEstimator` does, or read `-units=part` photon emission.
- **Driver wiring** (`concrete_irrad/run_contact_dose.py:37-54,77,89-90`), CONFIRMED.
  - `--nmpi` is never forwarded to `run_activation()` or `run_mavric()`.
  - The preview and single-run paths omit `mixer=ConcreteRebarMixer(**MIXER_PARAMS)`, so the README step 2 edits affect only `--scan`.
  - The driver tests stub these methods as `lambda self: ...`, which hides both defects.

### A5. `total_dose` uncertainty formula (CONFIRMED)

- `SampleDose.py:780-786` computes `total * sqrt(sum((sigma_i/v_i)^2))`. That is the propagation rule for a product.
- For a sum of absolute 1-sigma values the independent terms add as `sqrt(sum(sigma_i^2))`. The beta term is `k * gamma` and is fully correlated with gamma, so it adds linearly to the gamma sigma.
- Example: n = 1 +/- 0.1 and gamma = 100 +/- 1 give 10.15 from the code. The correct value is 1.005.
- `test/test_SampleDose.py:268-276` hard-codes the current formula.

### A6. Neutron source silently dropped; negative beta dose (CONFIRMED)

- `SampleDose.py:686-694` sets `beta_over_gamma = neutron_intensity = -1.0` when `_o.decayed_atom_dens` is empty. That happens whenever the ORIGEN case was not run in the current process.
- `mavric_deck()` then omits `src 1` while keeping the neutron adjoint source and tallies, so the neutron dose reads as about zero.
- `get_responses` sets beta = -gamma, so `total_dose` equals the neutron dose alone.
- The radiator workflow always takes this path. `examples/radiator/radiator_doses_decaytime.py` reads the burned material without decay, and `Radiator.py:26,205,235` inherits the sentinel. For fluoride fuel salt the F-19 (alpha,n) neutron source is significant.
- Suggestion: compute the spectral ratios from the F71 when the object was not run, or raise.

### A7. Beta dose reported behind shielding (CONFIRMED)

- `SquareTank`, `StorageTank` and `GenericTank` inherit `get_responses` (`SampleDose.py:760-763`). Beta is `beta_over_gamma` times the gamma dose *behind the shield layers*, and `total_dose` includes it.
- `README.md:14-16` states that the beta estimate assumes an unshielded sample. `examples/storage_tank_doses_scan_parallel.py` states that beta is zero with shielding.

### A9. `play/body_atom_density.py` composition and citation (CONFIRMED)

Owner clarification: the intended quantity is the average adult whole body (all tissues, skeleton included). The whole-body composition in the code is therefore the right kind of data. The defects are the citation and the soft-tissue labelling, listed below.


- `:43-60` cites "ICRU Report 89 ... Reference Values of Elemental Composition of Human Tissues (2005)". ICRU Report 89 (2016) covers cervical brachytherapy.
- The mass fractions (O 65, C 18.5, H 9.5, N 3.3, Ca 1.5, P 1.0) are the common whole-body composition, which includes the skeleton.
- The commit message and header call it soft tissue at 1.05 g/cm^3. ICRU-44 soft tissue (NIST Table 2) is:
  - H 10.2, C 14.3, N 3.4, O 70.8 wt%
  - Na 0.2, P 0.3, S 0.3, Cl 0.2, K 0.3 wt%
  - density 1.06 g/cm^3
- Effect on atom densities:
  - H comes out about 7% low (5.97e-2 at/(b cm)).
  - Ca is 2.4e-4 at/(b cm); soft tissue has essentially no Ca.
- `:19-20,107-109` say "~5.1 atoms per nucleon". The script prints 6.49 u per atom, which is about 6.5 nucleons per atom (0.154 atoms per nucleon).
- If whole-body is intended, ICRP Publication 23 or 89 is the matching reference.

### A11. Library correctness (sample_decay_dose)

- **FluorideSaltMixer lanthanide molar-volume cache** (`FluorideSaltMixer.py:372-396`), CONFIRMED. The LaF3 reference molar volume is cached at the first temperature. `"90%LiF-10%CeF3"` evaluated at 900 K and then 1200 K gives 2.5366 g/cm^3. A fresh object gives 2.5136 at 1200 K.
- **`from_atom_densities` fails on realistic inventories** (`FluorideSaltMixer.py:179-237`), CONFIRMED:
  - Valence-0 elements get one fluorine (`XeF`, `MoF`).
  - Halogens (valence -1) raise.
  - An Al impurity becomes `AlF3` and shifts the UF3/UF4 ratio from 0.08 to 0.0885.
  - `Am-242` and `Am-242m` collide in the breakdown.
  - Rounding to 6 decimals fails the 1e-6 sum check in 8 of 300 random salts.
- **Single-letter cation with enrichment** (`FluorideSaltMixer.py:547`), CONFIRMED. `re.match(r"([A-Z][a-z]?)", salt, re.IGNORECASE)` turns `KF` into `Kf`. Removing `re.IGNORECASE` fixes it.
- **UF3 adjustment is not mass-consistent** (`FluorideSaltMixer.py:440-448`), CONFIRMED. F atoms are removed while the mass density stays fixed (-0.35% at 22% UF4, ratio 0.08).
- **OPUS integrator double-counts adjacent equal bins** (`read_opus.py:31-41`), CONFIRMED. `prev_x` persists after a bin closes, so bins 5, 5, 1 integrate to 21 instead of 11. `test_integrate_opus_single_bin_is_zero` passes because its input lacks the leading space the regex needs.
- **Empty `layers_mats` produces an undefined body** (`SampleDose.py:1045,1145,1234,1490`; `HotCell.py:31-83`), CONFIRMED. `media 0 1 99999 -{k+2}` references a cylinder that does not exist. Only `HandlingContact...` (`:1326`) has the bare-sample fix.

- **`OrigenFromTritonMHA` zero-day state** (`SampleDose.py:287-289`), CONFIRMED. A 0-day deck sets `SAMPLE_F71_position = 2` permanently, and a later `set_decay_days(30)` raises "Too few time steps".
- **`HandlingContact.get_responses` parse failure** (`SampleDose.py:1374-1391`), CONFIRMED. An unmatched regex returns `responses = {}` and a total of zero without raising. `os.chdir` has no `try`/`finally`.

- **Base detector placement** (`SampleDose.py:929-938`), CONFIRMED. The detector is 30 cm from the sample centre with no check against the sample radius. At 5e5 cm^3 the radius is 43 cm, so the detector sits inside the sample.
- **Layer list lengths validated only in `__init__`** (`SampleDose.py:988`), CONFIRMED. Every example assigns the lists afterwards. With four thicknesses and three materials, the fourth layer is omitted from the geometry but kept in `case_dir`.
- **`OrigenDecayBox.case_dir` collisions** (`SampleDose.py:538-542`), CONFIRMED. The name encodes volume (labelled `_g`) and ignores decay time and composition.

### A12. Remote execution (gw_exe)

- **SSH arguments are not quoted** (`gw_exe/scalerte_ssh_client.py:31-36`), CONFIRMED by simulating the OpenSSH join. OpenSSH joins remote words with spaces for the remote shell.
  - The README example `--cmd "scalerte input.inp"` arrives as two tokens, and the agent rejects it.
  - A `--cmd` containing `&&` runs its tail on the login node instead of the worker.
  - Suggestion: pass `shlex.join([agent_command, *args])` as a single remote argument.
- **Jobs whose worker dies stay RUNNING** (`scalerte_ssh_agent.py:66-80`), CONFIRMED by reading. The agent has no liveness check, so `wait()` without a timeout never returns. The job still counts against `_pick_worker`. There is no cancel command.

## Resolution (working tree, not committed)

All items above are addressed in the working tree except the one withdrawn `th-irrad.py` claim. `pytest -q` passes 283 tests. The unittest runner passes 110. A wheel built from the tree ships the console scripts, the package data and all six DCF tables.

### Changes a user will notice

- **DCF tables (A1, A2).**
  - Both FGR-11 CSVs were re-extracted by a rewritten `extract_fgr11_dcf.py` from the page images of two scans. Every row passes the ICRP-26 weighted-sum check within 1.2%.
  - The ICRP-72 tables were re-extracted from `ANIB_26_1.pdf` by the new `extract_icrp72_dcf.py`. The absorption type of each table is documented in `leaky_box_origen/README.md`.
  - The new `dcf_icrp72_inhalation_adult_max.csv` holds the largest value over Types F, M and S.
  - Anchor values after the fix:

    | Nuclide | Table | Before | After |
    |---|---|---|---|
    | Pu-238 | FGR-11 inhalation | 1.06e-9 | 1.06e-4 Sv/Bq |
    | Co-60 | FGR-11 inhalation | 7.65e-9 | 5.91e-8 Sv/Bq |
    | Sr-90 | FGR-11 inhalation | absent | 3.51e-7 Sv/Bq |

  - `test/test_dcf_tables.py` checks anchor nuclides in every table.
  - Dose output gains `activity_fraction_without_dcf [-]`.
- **Leaky box (A10).**
  - Release rates now count only the nine removed elements, so inhalation doses from box inventories are lower.
  - Case directories carry the run prefix.
  - `Case1F71DecaySeries` tracks F-18, and its CSV columns are renamed to `tracked_nuclide` and `tracked_activity_bq`.
- **Dose totals (A4, A5, A7).**
  - `total_dose` sigma is the absolute sum in quadrature, with beta correlated to gamma.
  - The handling/contact estimators return the contact dose from `total_dose` and expose `contact_dose` and `handling_dose`.
